# 网络抓包与 Mock 助手设计与实施方案

## 一、背景与目标

在 Android 移动端测试与开发过程中，抓包（HTTP/HTTPS 报文分析）与 Mock（接口数据伪造/异常分支测试）是最高频、但也最繁琐的操作之一。传统方式依赖 Charles、Whistle 或 Fiddler 等重型工具，测试人员面临诸多痛点：
1. **配置繁琐**：每次都需要查询电脑局域网 IP，在手机 Wi-Fi 繁琐输入代理和端口；
2. **容易断网**：测试结束后经常忘记在手机中还原代理，导致手机彻底断网；
3. **证书门槛高**：Android 7.0+ 系统对用户凭据限制严格，第三方非 Debug 包抓包只能看到 `tunnel://`，证书安装与提升为系统根证书流程复杂；
4. **Mock 操作门槛高**：修改状态码、制造 500/401 异常、测试超时、修改 JSON 字段等需要复杂的规则配置。

**本方案目标**：在 ADB Tool 中内置**轻量、开箱即用、专为测试人员设计的集成抓包与 Mock 助手**，实现“一键全自动代理、一键安装证书、实时流量查看、傻瓜式 Mock 篡改”。

## 三、核心功能模块设计

### 模块 1：CA 根证书全自动生成与安装
* **自动生成根证书**：首次启动或在后台自动使用 `crypto/x509` 生成 2048 位 RSA 根证书（`ADBTool_CA.crt` 与私钥），保存在缓存目录（`~/.adb-tool-cache/ca/`）。
* **自动计算 Android 证书 Hash**：后端自动计算 X509 Subject Old Hash（例如 `9a5ba575.0` 格式）。
* **双模一键安装到设备**：
  * **普通安装（免 Root）**：ADB 推送到 `/sdcard/Download/`，并通过 Intent 调起系统证书安装器（`am start -a android.credentials.INSTALL`）。
  * **系统级安装（Root 手机 / 模拟器）**：利用 `adb root` + `adb remount`（或 tmpfs 挂载覆盖技术），将 `<hash>.0` 写入 `/system/etc/security/cacerts/` 并赋予 `644` 权限，彻底打通 Android 7.0+ 抓包。

### 模块 2：设备网络全自动托管（生命周期管理）
* **自动探测电脑 IP**：后端通过 Go 自动枚举本机活跃局域网 IP（`192.168.x.x` / `10.x.x.x`）。
* **双代理模式支持**：
  * **局域网 Wi-Fi 模式**：调用 `adb shell settings put global http_proxy <PC_IP>:9877`。
  * **USB 逆向反向代理模式（免同 Wi-Fi）**：调用 `adb reverse tcp:9877 tcp:9877`，手机代理设为 `127.0.0.1:9877`，即使手机处于 4G/5G 流量也能直接抓包。
* **防断网防护（Fail-Safe）**：
  * 点击“停止抓包”、应用正常退出、拔出设备或后端异常退出时，自动执行 `settings put global http_proxy :0`，确保手机网络立刻恢复。

### 模块 3：极简抓包控制台（Traffic Inspector）
* **请求列表（左侧）**：
  * 状态码色彩指示（200 绿、3xx 蓝、4xx 橙、5xx 红、Mocked 紫）。
  * 显示 Method、Host、Path、耗时、响应大小。
  * 支持域名、URL、状态码关键字快速筛选过滤。
  * 右键菜单：复制完整 URL、复制 cURL 命令、一键“以此接口创建 Mock 规则”。
* **报文详情（右侧 Tab）**：
  * **Overview**：常规元数据（请求方式、完整 URL、耗时、协议、时间戳）。
  * **Headers**：请求与响应 Header 列表。
  * **Response**：JSON 自动格式化、语法着色、折叠展开、一键复制。

### 模块 4：测试专用 Mock 与响应篡改（Response Rewriter）
* **规则匹配**：支持按 URL 关键字匹配、前缀匹配或正则表达式匹配。
* **开箱即用场景模板**：
  * 一键模拟服务端异常：强行返回 HTTP 500。
  * 一键模拟未登录/登录过期：强行返回 HTTP 401。
  * 一键模拟空列表/空数据：返回 `{ "code": 0, "data": [] }`。
  * 一键模拟弱网延迟：注入延迟 N 毫秒响应。
* **可视化编辑**：直接在界面文本框中修改返回的 JSON 结构，保存即生效。

## 四、实施阶段与排期

| 阶段 | 核心任务 | 交付物 |
|---|---|---|
| **Phase 1: Go 后端核心引擎** | 1. 编写 CA 证书生成与 Hash 计算器 (`backend/internal/proxy/ca.go`)<br>2. 搭建 MITM 代理服务 (`backend/internal/proxy/server.go`)<br>3. 实现 ADB 代理设置/清除与证书推送 (`adb_proxy.go`)<br>4. 编写 HTTP 路由与 WebSocket 流量通道 (`handlers_proxy.go`) | 后端可通过 API/命令完成自签证书生成、手机代理一键开启、实时抓包报文流推送 |
| **Phase 2: Flutter 界面与抓包闭环** | 1. 侧边栏新增「抓包调试」导航入口<br>2. 编写 `ProxyApiClient` 与 `TrafficProvider`<br>3. 搭建顶部启停控制栏与证书安装引导弹窗<br>4. 搭建实时请求列表与右侧 JSON/Headers 详情展示 | 桌面端可一键开启/停止抓包，实时查看 Android 设备网络请求与响应详情 |
| **Phase 3: 傻瓜式 Mock 响应篡改** | 1. 后端实现 Mock 规则匹配引擎与响应改写逻辑<br>2. 前端实现 Mock 规则抽屉与创建弹窗<br>3. 接入常用异常模板（500、401、延迟、空数据） | 测试人员可在界面上直接篡改接口返回数据，测试 App 异常分支 |
| **Phase 4: 体验增强与防呆测试** | 1. 接入 USB 反向代理模式 (`adb reverse`)<br>2. 软件退出/异常断连自动清空手机代理防护<br>3. 单元测试与端到端回归测试 | 完整功能打磨，开箱即用，零门槛交付测试人员使用 |
